# UI & Design System Specification (v2.1)

## Design Vision

UrbanInsight AI is an AI-assisted urban exploration platform rather than a traditional dashboard.

The experience should feel like exploring a living city alongside an intelligent urban analyst.

The map is the visual focus of the initial experience.

Information is disclosed progressively after borough selection.

The interface supports English and Simplified Chinese without separate layouts.

---

# Design Principles

## Core Principles

- Map-first experience
- AI-guided interaction
- Progressive information disclosure
- Minimal cognitive load
- Clear separation of statistics and interpretation
- Bilingual layout resilience

## Personality

The interface should feel:

- Modern
- Friendly
- Intelligent
- Calm
- Premium
- Editorial

Avoid:

- Enterprise KPI walls
- Technical GIS software styling
- Dense tables
- Heavy gradients
- Dark AI interfaces
- Repeated instructions
- Nested cards without a clear framing purpose

# Top Navigation

The header is sticky.

Left

- Sparkles product mark
- `UrbanInsight AI`

Center

- Borough search

Right

- `AI Insights` / `AI 深度解读` switch
- DeepSeek / Qwen provider selector
- Language switcher

The AI switch defaults to off, persists under
`urbaninsight-ai-insights-enabled`, and affects new analyses only. Changing it after
completion shows a lightweight notice that the setting applies to the next analysis.
The switch never displays provider, mock, live or development terminology.

The provider selector is enabled when AI Insights is on. Its values are `deepseek`
and `qwen`, displayed as DeepSeek and Qwen/千问. The preference is stored under
`urbaninsight-ai-provider`. Switching provider after analysis completion affects the
next analysis only.

The previous Run Analysis, Settings and account actions are obsolete.

Selecting a borough directly triggers the analysis workflow.

The search and language controls must not compress into unusable widths.

# Search Specification

The borough search is functional.

Behavior

- Case-insensitive substring matching
- Results limited to six
- Official borough names remain in English
- Selecting a result triggers the same workflow as a map click
- `Enter` selects the first result
- `Escape` closes the result list
- Clicking outside closes the list
- Clear button empties the query
- Selected borough name is synchronized into the input

Search is responsible for finding boroughs.

It should not repeat map interaction instructions.

# AI Panel

The AI Panel is a sticky contextual assistant.

It contains:

- UrbanInsight identity
- Current interaction state
- Analysis progress
- Completed score summary
- Follow-up conversation
- Borough comparison control

States

- `idle`
- `hover`
- `selected`
- `analyzing`
- `completed`

Idle and hover use the same outer layout, spacing, card style and hierarchy.

Only the content changes.

Idle explains what UrbanInsight AI does.

Hover previews the borough and invites selection.

Selected and analyzing show a five-step progress list.

Completed steps use completed-language labels. A completed icon must never appear
beside an in-progress label. Basic analysis uses the indicator and Analysis Engine
stages only; AI-enabled analysis adds context, interpretation and recommendation stages.

Completed shows:

- Borough name
- Overall score
- Regional rank
- Localized error or follow-up guidance

Conversation becomes available only when analysis is complete and a borough ID is known.

Messages are displayed in a bounded scroll area.

AI responses are not streamed.

# Analysis Workspace

The workspace is hidden before completion.

It appears with the `panel-in` transition.

Sections

1. Borough heading and report action
2. Overall score, rank and summary
3. Economic, Social and Ecological cards
4. Radar chart
5. Contribution bar chart
6. Twelve indicator cards
7. Main drivers and indicator interpretation
8. Strengths
9. Weaknesses
10. Recommendations
11. PDF and Markdown report actions

The top and bottom report action groups share the same handlers and one loading
state. PDF is the primary action; Markdown is the secondary action. While either
format is being generated, both groups are disabled to prevent duplicate exports.

The report type is frozen by the completed analysis, not the current header switch:

- Basic → `UrbanInsight 基础分析报告`
- AI applied successfully → `UrbanInsight AI 深度分析报告`

PDF reports include a cover, score and rank summary, PCA contribution bars,
dimension radar, indicator table, interpretation, recommendations, methodology,
disclaimer, page headers and page numbers. The PDF locale follows the current UI
locale. Export uses the completed analysis metadata and insights snapshot and does
not call an AI provider again.

Statistical scores and contributions come from the Analysis Engine.

Narrative insights come from the AI provider.

Basic analysis and AI failure fallback use the complete preset interpretation,
including drivers, strengths, weaknesses and recommendations. Provider failure must
not remove those cards or label preset content as live AI output.

If stored statistical data is unavailable, the workspace can show a localized preview profile.

# Internationalization

Supported locales

- `en`
- `zh-CN`

Behavior

- Saved `localStorage` preference wins
- Chinese browser locales default to `zh-CN`
- All other browser locales default to English
- Language changes update the document `lang`
- The preference is stored under `urbaninsight-language`

Official London borough names remain in English.

Indicator labels are translated from stable indicator IDs.

New AI requests use the current locale.

Existing AI content is not regenerated when the UI language changes.

# Motion System

Use subtle motion only.

| Interaction | Duration |
|---|---:|
| Fast UI transition | 150ms |
| Card or panel transition | 250ms |
| Map movement | 300ms |
| Slow content transition | 400ms |

Avoid bounce animations.

Avoid excessive scaling.

Loading progress may pulse.

The application does not currently implement skeleton loading or streamed typing.

# Responsive Design

Desktop

- 7:3 map and AI grid
- Sticky AI Panel
- Three-column dimension and insight groups

Tablet and narrow desktop

- Main grid stacks below 1024px
- Analysis sections reduce columns progressively

Mobile

- Header remains a single row
- Map retains 640px minimum height
- AI Panel follows the map
- Cards and actions stack

A bottom-sheet AI Panel and floating mobile action button are not implemented.

---

# Accessibility

Requirements

- 44px minimum application control height
- Visible hover and keyboard focus states
- Search uses combobox and listbox semantics
- Language menu uses menu and radio semantics
- Progress and message regions use live-region behavior
- Map zoom and Home controls have localized labels
- Decorative icons use `aria-hidden`
- Color is supplemented by labels and icons

The map itself uses a labeled region.

---

# Design Anti-patterns

Never imitate enterprise BI dashboards.

Never overload the initial screen with statistics.

Never cover the map with a large instruction panel.

Never duplicate selection guidance across search, map and AI Panel.

Never use excessive gradients.

Never use tiny fonts.

Never display large data tables on the initial screen.

Never make the AI resemble a detached generic chatbot.

---

# Overall Experience

The interface should make users feel:

> I am exploring a city together with an AI urban analyst.

rather than:

> I am reading a data dashboard.
