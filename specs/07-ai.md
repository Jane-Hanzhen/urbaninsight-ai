# AI Decision Agent Specification

## Overview

The AI Decision Agent interprets authoritative results produced by the Analysis Engine.

It supports initial analysis, follow-up conversation, borough comparison and Markdown report generation.

The AI layer is provider-agnostic.

The frontend uses the same endpoints in Mock AI and Live AI modes.

The AI must never calculate or modify PCA, TOPSIS, scores, contributions or rankings.

---

# AI Responsibility

The AI Agent may:

- Explain stored rankings
- Interpret stored indicators
- Identify main drivers
- Summarize strengths
- Summarize weaknesses
- Generate recommendations
- Compare stored borough results
- Answer contextual questions
- Generate reports

The AI Agent must not:

- Calculate PCA
- Calculate TOPSIS
- Derive new weights
- Generate a new ranking
- Change stored values
- Invent missing values
- Claim causality that the data does not support

---

# Provider Strategy Pattern

All providers implement one interface.

Required provider capabilities

- Return provider name
- Return configured model
- Report whether configuration is complete
- Generate structured `AnalysisInsights`
- Generate normal text

The abstract interface is:

```text
AIProvider
├── name
├── model
├── is_configured()
├── generate_insights(prompt)
└── generate_text(prompt)
```

Live providers inherit from `OpenAICompatibleProvider`.

They use the OpenAI Python SDK and non-streaming Chat Completions.

# AI Modes

## Mock Mode

Configuration

```text
AI_MODE=mock
```

Behavior

- Never initializes an external LLM client
- Never uses an API key
- Ignores `AI_PROVIDER`
- Reports provider `mock`
- Reports model `urbaninsight-mock`
- Returns predefined structured insights
- Returns predefined chat, comparison and report text
- Supports English and Simplified Chinese
- Simulates 300–800ms latency

Mock mode is the required mode for routine UI development.

## Live Mode

Configuration

```text
AI_MODE=live
```

Behavior

- Resolves `AI_PROVIDER`
- Creates the selected provider strategy
- Requires the active provider API key for generation
- Uses the configured provider model and base URL
- Makes external API calls

If `AI_MODE` is omitted, the backend defaults to `live`.

If `AI_PROVIDER` is omitted in live mode, the backend defaults to `openai`.

Unsupported modes or providers raise configuration errors.

# Prompt Builder

The Prompt Builder is:

```text
backend/app/ai/prompt_builder.py
```

System rules

- Use only supplied Analysis Engine context
- Treat statistical values as immutable
- Never calculate or estimate missing results
- Distinguish evidence from recommendations
- Avoid unsupported causal claims
- Keep decision support concise and practical

Every prompt includes:

- Selected borough context
- Optional comparison borough context
- Up to 12 prior conversation messages
- Explicit output-language instruction

Prompt types

- Initial analysis prompt
- Follow-up chat prompt
- Comparison prompt
- Markdown report prompt

The context is serialized as formatted, sorted JSON.

Raw prompt text must not be sent to the frontend or written to normal logs.

# Structured AnalysisInsights

`POST /ai/analyze` accepts `include_ai_insights`.

When false, it uses the existing preset provider to return complete deterministic
`AnalysisInsights` without an external API call. When true, it uses the request
`ai_provider` to create a live DeepSeek or Qwen provider. If omitted, `AI_PROVIDER`
is the server default. `AI_MODE=mock` does not override an explicit web analysis
request.

Provider configuration or request failure returns the same complete preset insights
as a basic fallback, with metadata showing that live AI was requested but not applied.

Response envelope

```json
{
  "analysis_mode": "ai",
  "ai_insights_requested": true,
  "ai_insights_applied": true,
  "ai_provider": "deepseek",
  "ai_model": "configured model",
  "ai_error": null,
  "insights": {}
}
```

`analysis_mode` is `basic` unless live insights were successfully validated.
`insights` is always present for a successful analysis response.

Schema

```json
{
  "executive_summary": "string",
  "ranking_explanation": "string",
  "main_drivers": [
    {
      "title": "string",
      "detail": "string"
    }
  ],
  "strengths": [],
  "weaknesses": [],
  "indicator_interpretation": "string",
  "recommendations": [
    {
      "title": "string",
      "detail": "string",
      "priority": "High"
    }
  ]
}
```

Cardinality

- `main_drivers` → 2–4 items
- `strengths` → 2–4 items
- `weaknesses` → 2–4 items
- `recommendations` → 2–4 items

Recommendation priority

- `High`
- `Medium`

Live providers are instructed to return one JSON object only.

The request asks for JSON object output.

Provider content is parsed with `json.loads` and validated with Pydantic.

JSON code fences are tolerated and removed.

Invalid JSON or schema failure becomes a sanitized provider response error.

# Report Generation

Markdown endpoint

```text
POST /ai/report
```

The AI returns Markdown only.

Required sections

- Executive Summary
- Regional Evaluation
- Key Indicators
- Strengths
- Weaknesses
- Recommendations

The report must begin with a level-one title.

`POST /ai/report` also accepts `include_ai_insights`.

- `false` reuses the preset report response and normalizes its title
- `true` uses the provider recorded by the completed analysis and normalizes the title

Titles

- English basic: `UrbanInsight Basic Analysis Report`
- English AI: `UrbanInsight AI In-depth Analysis Report`
- Chinese basic: `UrbanInsight 基础分析报告`
- Chinese AI: `UrbanInsight AI 深度分析报告`

The frontend converts the response into a Markdown download.

PDF endpoint

```text
POST /reports/pdf
```

PDF generation is deterministic document rendering, not an AI operation. The
frontend supplies the completed `AnalysisInsights` and completed-analysis metadata;
the backend reloads the authoritative borough indicators and stored Analysis Engine
result from SQLite. It then renders a bilingual A4 report with ReportLab.

The PDF route must not call `generate_insights`, `generate_text`, or any external
provider. The report title, provider/model disclosure and fallback note are derived
from `ai_insights_applied` and the other frozen completion metadata, not from the
current header controls.

PDF is the primary user-facing export. Markdown remains available as a secondary,
editable format.

# Language Support

Supported locale values

- `en`
- `zh-CN`

English is the default when `locale` is omitted.

Unsupported locale values fail request validation.

The requested locale applies to:

- Initial analysis
- Follow-up chat
- Borough comparison
- Report generation

Keep these values unchanged:

- Official borough names
- Database IDs
- Indicator IDs
- JSON field names
- Numerical values
- `High` and `Medium` schema values

Changing the frontend language affects new requests only.

Existing responses remain in their original language.

# Error Handling

Configuration errors

- Missing active provider key → generation fails with service unavailable
- Unsupported mode → service unavailable
- Unsupported provider → service unavailable

Provider API errors

- Log provider name
- Log exception type
- Log HTTP status when available
- Log request ID when available
- Log sanitized error and cause
- Return generic `502` detail

Provider response errors

- Log provider name
- Log exception type
- Log sanitized message
- Return generic `502` detail

Sanitization removes:

- Configured provider keys
- Strings matching common `sk-...` key patterns

The frontend displays localized generic errors.

# Security

Never:

- Commit API keys
- Put keys in frontend environment variables
- Return keys from status endpoints
- Log raw API keys
- Expose raw provider exceptions to the frontend
- Send prompts to browser logs

Secrets belong only in:

```text
backend/.env
```
